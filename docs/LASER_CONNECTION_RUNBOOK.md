# Лазер: проверенный порядок подключения и загрузки RD

Сохранено по просьбе владельца 29 сентября 2026. Основание — задача **«Продолжить разработку»**, ID `01a0ecd3-1fd4-7fe3-9566-315dcdedc0c4`, и подтверждение владельца: **«резка прошла успешно»** для `RELTEST2`.

## Что уже известно

- **Подтверждено владельцем 29.09.2026 на задании #10846:** четыре файла загрузились через Hub; после исправления имён и добавления Reload владелец сообщил «все работает». Повторную загрузку выполнял сам владелец через интерфейс. Это подтверждение передачи; не считать его основанием автоматически отмечать будущую резку выполненной.

- Станок подключён к этому Windows-компьютеру по Ethernet. Проверенный IP контроллера: **192.168.1.100**. В предыдущей проверке адрес компьютера был **192.168.1.110**; это наблюдение, не команда менять настройки адаптера.
- Ruida: отправка UDP на **50200**, локальный порт отправщика **40200**. RDWorks должен быть закрыт, чтобы не занимать этот порт.
- Рабочий отправщик: `scripts/packing-station/ruida-udp.mjs`, функция `sendRdFile`. Проверенная версия принимает `filename` и отправляет команду сохранения имени **до** байтов RD-файла.
- `Test.rd` был загружен нашим кодом под именем **RELTEST2**. Имя прочитано из памяти контроллера отдельным запросом. Владелец подтвердил появление файла и успешную ручную резку.
- Предыдущие тайм-ауты были вызваны **ограниченным UDP-доступом среды выполнения**. Ping проходил, но UDP не отвечал. Та же проверка и загрузка вне ограничения сработали. Не начинать заново менять протокол или файл только на основании такого тайм-аута.
- **Резку запускает только оператор с панели станка.** Загрузка файлов и подтверждение их приёма не означают, что коробки вырезаны.

## Порядок действий в следующей задаче

1. Сначала прочитать этот файл и `docs/PACKING_LASER.md`. Использовать известный IP; повторно спрашивать его только при признаках изменения подключения.
2. Проверить текущую копию отправщика: она должна принимать `filename` и отправлять команду имени до данных. Интеграция станции использует `transfer-task.mjs`: сначала скачивает и проверяет все файлы, затем передаёт их по очереди. Уточнение владельца 30.09.2026: `.rd` — расширение файла, а не часть имени задания на станке. Передавать **имя без последнего расширения `.rd`**: `D1.rd` → `D1`, сохраняя регистр, пробелы и остальные точки. Прежнее указание включать расширение было ошибкой и отменено. Нельзя сокращать само имя или заменять его хешем. Текущая проверка отправщика допускает печатные ASCII-имена до 255 байт без разделителей пути; если имя невозможно передать без изменения, показывать ошибку до передачи.
3. Убедиться, что RDWorks закрыт и порт 40200 свободен. Не завершать процессы вслепую. Прочитать состояние сети без изменения настроек:

   ```powershell
   Test-Connection 192.168.1.100 -Count 1
   Get-Process RDWorksV8 -ErrorAction SilentlyContinue
   Get-NetUDPEndpoint -LocalPort 40200 -ErrorAction SilentlyContinue
   ```

4. Проверить UDP служебным запросом без загрузки файла. Успешный ping сам по себе недостаточен. В Codex запускать сетевую проверку и разрешённую загрузку с `sandbox_permissions: require_escalated`, если среда ограничивает UDP. Не отключать firewall и не менять настройки безопасности вместо получения штатного сетевого доступа. Соблюдать результат проверки разрешений.
5. Перед загрузкой определить **конкретный файл и имя для контроллера без последнего `.rd`**. Проверить путь, размер и при необходимости SHA-256. Не придумывать отдельное имя для контроллера. При совпадении имён с разным содержимым остановить задание и сообщить о конфликте; уже подтверждённый неизменившийся файл повторно не отправлять без необходимости.
6. Использовать существующий `sendRdFile(data, {address:'192.168.1.100', filename, timeoutMs:5000})`. Он сохраняет именованный файл: кодирует команду имени, добавляет контрольную сумму и ждёт `C6` на каждый пакет. Байты экспортированного `.rd` повторно не кодировать. Не отправлять только сырые данные без команды имени: ранняя попытка создала `TempFile`.
7. После успешных ACK проверить **имя в Memory File** на панели или отдельным проверенным запросом чтения памяти. ACK не заменяет эту проверку. При тайм-ауте остановиться, проверить память и сетевой доступ; не повторять передачу вслепую.
8. Оператор выбирает файл, проверяет Origin/Frame и запускает резку вручную. Для проверенного `Test.rd` использовался экспорт RDWorks **Position: Anchor point**. Это свойство экспортированного файла: отправщик не должен автоматически менять координаты, мощность, скорость или режим других RD-файлов.
9. Статус **Boxes made / completed** ставить только после подтверждения оператором фактического окончания резки всех файлов в требуемом количестве. Передача файлов не должна автоматически завершать задание или менять стадию изделия в Production Board.

## Проверенный служебный UDP-запрос

Этот пример только проверяет ответ контроллера; файл не загружает и резку не запускает. Выполнять с разрешённым сетевым доступом, при свободном локальном порте 40200:

```javascript
import dgram from 'node:dgram';
const socket = dgram.createSocket('udp4');
let timer;
const finish = () => { clearTimeout(timer); socket.close(); };
socket.once('error', error => { console.error(error.message); finish(); });
socket.once('message', reply => {
  console.log('Controller reply:', reply.toString('hex')); // ожидается c6
  finish();
});
socket.bind(40200, () => socket.connect(50200, '192.168.1.100', () => {
  timer = setTimeout(() => { console.error('No UDP reply'); finish(); }, 4000);
  socket.send(Buffer.from([0x00, 0xc8, 0xc8]));
}));
```

## Отдельно: подключение кнопки Hub

Передача четырёх файлов через Hub и повторная загрузка с исходными именами **подтверждены владельцем**. Ручная резка тестового RELTEST2 подтверждена отдельно в предыдущей задаче. Интерфейс Boxes made и обновление Manage Packing проверены на тестовых данных; фактическое изготовление коробок конкретного задания подтверждает оператор.

`Cutting laptop offline` означает отсутствие свежего heartbeat программы станции в Hub; это не доказательство недоступности контроллера по Ethernet. Для кнопки требуется запущенная `scripts/packing-station/station.mjs` через `start.ps1 -ControllerIp 192.168.1.100`, публичная конфигурация Supabase и вход менеджера. Проверять актуальный код и настройки перед запуском: станция с `--send` обрабатывает очередь реальных передач. Пароли и токены не сохранять в документации, исходниках и логах.

Для автоматического запуска при входе в Windows используется `scripts/packing-station/install-autostart.ps1`. Установщик сохраняет отдельную копию станции в `%USERPROFILE%\WhiteCorner\PackingStation` и регистрирует задачу Windows `White Corner Packing Station` для входа текущего пользователя и восстановления каждую минуту. Прежний ярлык автозагрузки удаляется только после успешной регистрации задачи. Однократный вход менеджера сохраняется через Windows DPAPI в защищённой папке, не в репозитории и не в Task Scheduler. Сначала читать `setup-status.json` и проверять heartbeat Hub; не читать и не выводить `credential.xml`. Используется встроенный `powershell.exe`, команда `pwsh` в пользовательском PATH не найдена. Для запуска локальных скриптов `RemoteSigned` задаётся только процессу; системная политика не меняется. Подробнее — раздел Windows automatic startup в `PACKING_LASER.md`.

Эта инструкция сохраняет знания, но не даёт самостоятельного разрешения на передачу файлов, запуск станции, публикацию изменений или резку. После команды пользователя «Стоп» не возобновлять остановленную работу без нового указания.

## Повседневная работа — использовать этот порядок

1. При входе пользователя в Windows станция запускается автоматически и работает в фоне. Задача Windows **White Corner Packing Station** также проверяет восстановление каждую минуту, пока пользователь вошёл в Windows. Не просить каждый раз открыть PowerShell, ввести пароль или назвать IP. Установленная копия — `C:\Users\stasa\AppData\Local\WhiteCorner\PackingStation`; код из репозитория сам по себе эту копию не обновляет. В **Packing work** менеджер может нажать **Restart station** и подтвердить перезапуск: текущая загрузка завершается, новый процесс должен подтвердить соединение. **Refresh** только перечитывает данные Hub. Перезапуск не повторяет файлы и не запускает резку.
2. В Hub открыть **Packing → Packing work**. Должно быть **Cutting laptop connected**. Если offline — проверить задачу Windows, статус и журналы станции, затем сеть; не переустанавливать всё вслепую.
3. **Load N files to laser** ставит задание в очередь. Станция скачивает и проверяет все файлы, затем передаёт каждый с именем из Hub без последнего расширения `.rd`. Например, файлы **D1.rd, D2.rd, D3.rd, D4.rd** сохраняются на станке как **D1, D2, D3, D4**. В Hub исходные имена файлов не меняются. Хеш используется только для проверки совпадения содержимого. Разные исходные имена сохраняются отдельно, даже если содержимое одинаковое.
4. Статусы: **Sent to cutting → Loading to laser → Ready to cut**. Успех передачи ставится только после ACK всех файлов; при ошибке показывается причина. Количество copies — инструкция оператору, не команда станку повторять резку.
5. В **Ready to cut** доступна **Reload N files to laser**. Она использует `wc_request_packing_transfer`: разрешены `assigned` и `transferred`; активная очередь возвращает существующий запрос, а `completed`/`cancelled` запрещены. Успешный запрос сбрасывает локальную галочку окончания резки. Production-миграция: `20260929131500_packing_reupload.sql`. Номер `20260929000100` был занят другой production-миграцией — его не переиспользовать.
6. Проверить файлы в памяти контроллера. Резку запускает оператор с панели. После изготовления указанного количества для каждого RD-файла отмечать его отдельной галочкой **Done**. Каждая отметка сразу сохраняется в `wc_packing_tasks.cut_file_ids`; можно оставить 3 из 4, обновить страницу и продолжить позже. Галочку можно снять, и изменение также сохраняется. Последняя отметка только сохраняет прогресс через `wc_set_packing_file_done` и открывает отдельное окно подтверждения. Отмена оставляет задание открытым со всеми сохранёнными галочками; кнопка **Confirm boxes made** позволяет вернуться к подтверждению. Только явное подтверждение вызывает `wc_complete_packing_task`, который проверяет все файлы и атомарно закрывает задание. Это требует миграции `20260930000300_packing_completion_confirmation.sql`. В списке колонка **Copy** содержит числа, **Status** — галочки без повторяющегося Done; название состояния **Ready to cut** не меняется. Стадия изделия в Production Board от этого не меняется.
7. Обновляя локальную станцию, сначала убедиться, что передача окончена. Копировать проверенные файлы в установленную папку и перезапускать только точно определённый процесс станции; фоновый launcher повторно запускает Node через 15 секунд. Пароль повторно не спрашивать при обычном обновлении кода. Не удалять старые файлы из памяти контроллера автоматически.

Проверки предыдущего релиза: 400 Angular-тестов и production-сборка; 10 тестов станции; изолированные SQL-проверки повторной загрузки, отсутствия дубликатов и запрета завершения во время передачи. Production-интерфейс показал активную Reload для #10846, затем владелец подтвердил работу. Для сохранения отдельных галочек: 401 Angular-тест, production-сборка и изолированный SQL-тест сохранения 3/4, снятия отметки и завершения 4/4. Физическая резка и отметки конкретного задания остаются действиями оператора.
