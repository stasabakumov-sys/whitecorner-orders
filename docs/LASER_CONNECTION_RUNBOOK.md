# Лазер: проверенный порядок подключения и загрузки RD

Сохранено по просьбе владельца 29 сентября 2026. Основание — задача **«Продолжить разработку»**, ID `01a0ecd3-1fd4-7fe3-9566-315dcdedc0c4`, и подтверждение владельца: **«резка прошла успешно»** для `RELTEST2`.

## Что уже известно

- Станок подключён к этому Windows-компьютеру по Ethernet. Проверенный IP контроллера: **192.168.1.100**. В предыдущей проверке адрес компьютера был **192.168.1.110**; это наблюдение, не команда менять настройки адаптера.
- Ruida: отправка UDP на **50200**, локальный порт отправщика **40200**. RDWorks должен быть закрыт, чтобы не занимать этот порт.
- Рабочий отправщик: `scripts/packing-station/ruida-udp.mjs`, функция `sendRdFile`. Проверенная версия принимает `filename` и отправляет команду сохранения имени **до** байтов RD-файла.
- `Test.rd` был загружен нашим кодом под именем **RELTEST2**. Имя прочитано из памяти контроллера отдельным запросом. Владелец подтвердил появление файла и успешную ручную резку.
- Предыдущие тайм-ауты были вызваны **ограниченным UDP-доступом среды выполнения**. Ping проходил, но UDP не отвечал. Та же проверка и загрузка вне ограничения сработали. Не начинать заново менять протокол или файл только на основании такого тайм-аута.
- **Резку запускает только оператор с панели станка.** Загрузка файлов и подтверждение их приёма не означают, что коробки вырезаны.

## Порядок действий в следующей задаче

1. Сначала прочитать этот файл и `docs/PACKING_LASER.md`. Использовать известный IP; повторно спрашивать его только при признаках изменения подключения.
2. Проверить текущую копию отправщика: она должна принимать `filename` и отправлять команду имени до данных. Интеграция станции использует `transfer-task.mjs`: сначала скачивает и проверяет все файлы, затем передаёт их по очереди. Имена в контроллере — первые 8 символов SHA-256 содержимого; соответствие исходным именам выводится в окне станции. Публикация кода не заменяет живую проверку полной цепочки.
3. Убедиться, что RDWorks закрыт и порт 40200 свободен. Не завершать процессы вслепую. Прочитать состояние сети без изменения настроек:

   ```powershell
   Test-Connection 192.168.1.100 -Count 1
   Get-Process RDWorksV8 -ErrorAction SilentlyContinue
   Get-NetUDPEndpoint -LocalPort 40200 -ErrorAction SilentlyContinue
   ```

4. Проверить UDP служебным запросом без загрузки файла. Успешный ping сам по себе недостаточен. В Codex запускать сетевую проверку и разрешённую загрузку с `sandbox_permissions: require_escalated`, если среда ограничивает UDP. Не отключать firewall и не менять настройки безопасности вместо получения штатного сетевого доступа. Соблюдать результат проверки разрешений.
5. Перед загрузкой определить **конкретный файл и имя в памяти**. Проверить путь, размер и при необходимости SHA-256. Имя контроллера: 1–8 ASCII-букв, цифр, `_` или `-`. Использовать отдельное имя, чтобы не затереть другой файл. Уже подтверждённый неизменившийся файл повторно не отправлять без необходимости.
6. Использовать существующий `sendRdFile(data, {address:'192.168.1.100', filename, timeoutMs:5000})`. Он сохраняет именованный файл: кодирует команду имени, добавляет контрольную сумму и ждёт `C6` на каждый пакет. Байты экспортированного `.rd` повторно не кодировать. Не отправлять только сырые данные без команды имени: ранняя попытка создала `TempFile`.
7. После успешных ACK проверить **имя в Memory File** на панели или отдельным проверенным запросом чтения памяти. ACK не заменяет эту проверку. При тайм-ауте остановиться, проверить память и сетевой доступ; не повторять передачу вслепую.
8. Оператор выбирает файл, проверяет Origin/Frame и запускает резку вручную. Для проверенного `Test.rd` использовался экспорт RDWorks **Position: Anchor point**. Это свойство экспортированного файла: отправщик не должен автоматически менять координаты, мощность, скорость или режим других RD-файлов.
9. Статус **Boxes made / completed** ставить только после подтверждения оператором фактического окончания резки всех файлов в требуемом количестве. Передача файлов не должна автоматически завершать задание или менять стадию изделия в Production Board.

## Проверенный служебный UDP-запрос

Этот пример только проверяет ответ контроллера; файл не загружает и резку не запускает. Выполнять с разрешённым сетевым доступом, при свободном локальном порте 40200:

```javascript
import dgram from 'node:dgram';
const socket = dgram.createSocket('udp4');
let timer;
const finish = () => { clearTimeout(timer); socket.close(); };
socket.once('error', error => { console.error(error.message); finish(); });
socket.once('message', reply => {
  console.log('Controller reply:', reply.toString('hex')); // ожидается c6
  finish();
});
socket.bind(40200, () => socket.connect(50200, '192.168.1.100', () => {
  timer = setTimeout(() => { console.error('No UDP reply'); finish(); }, 4000);
  socket.send(Buffer.from([0x00, 0xc8, 0xc8]));
}));
```

## Отдельно: подключение кнопки Hub

Прямая загрузка через отправщик **проверена**. Полная цепочка **Load to laser → станция → четыре RD-файла → ручная резка → Boxes made** на дату записи ещё **не проверена целиком**.

`Cutting laptop offline` означает отсутствие свежего heartbeat программы станции в Hub; это не доказательство недоступности контроллера по Ethernet. Для кнопки требуется запущенная `scripts/packing-station/station.mjs` через `start.ps1 -ControllerIp 192.168.1.100`, публичная конфигурация Supabase и вход менеджера. Проверять актуальный код и настройки перед запуском: станция с `--send` обрабатывает очередь реальных передач. Пароли и токены не сохранять в документации, исходниках и логах.

Для автоматического запуска при входе в Windows используется `scripts/packing-station/install-autostart.ps1`. Установщик сохраняет отдельную копию станции в `%LOCALAPPDATA%\WhiteCorner\PackingStation` и создаёт ярлык `White Corner Packing Station.lnk` в автозагрузке текущего пользователя. Однократный вход менеджера сохраняется через Windows DPAPI в защищённой папке, не в репозитории. Сначала читать `setup-status.json` и проверять heartbeat Hub; не читать и не выводить `credential.xml`. Используется встроенный `powershell.exe`, команда `pwsh` в пользовательском PATH не найдена. Для запуска локальных скриптов `RemoteSigned` задаётся только процессу; системная политика не меняется. Подробнее — раздел Windows automatic startup в `PACKING_LASER.md`.

Эта инструкция сохраняет знания, но не даёт самостоятельного разрешения на передачу файлов, запуск станции, публикацию изменений или резку. После команды пользователя «Стоп» не возобновлять остановленную работу без нового указания.
